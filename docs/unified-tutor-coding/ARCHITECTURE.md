# Implementation boundaries

`coding_teaching.py` is pure shared teaching data/composition. The Assessment facade retains compatibility imports, exact UC100N checks, concepts-only exam behavior, question consent, full-solution allowlist and ephemeral signed continuity. It never imports Tutor persistence. Existing helper tests characterize this extraction.

`CodingRequest` rejects unknown fields, invalid enums, non-boolean consent flags, bool-as-integer revisions and oversized code/context. Text remains literal UTF-8, preserving whitespace. Language capabilities enable Python export only. No application path compiles, evaluates, imports or executes submitted code.

`TutorCodingService` resolves the canonical local owner through the existing web service. Its dedicated routes require loopback Host, same Origin when supplied, no cross-site Fetch metadata, CSRF and the activation flag. Nested task IDs resolve through their requested session, never matching hashes or filenames. There is no multi-user authentication or remote/LAN feature.

Task creation is idempotent by request identity plus a digest of validated task content. Updates/archive compare revisions. The optional `tutor_coding_turn_context` links existing user/assistant turns to one task and validated semantic request. A SQLite trigger enforces same-session roles. Request/source JSON are byte capped. Assistant content is not duplicated. Receipts are durable, with unique `(task_id,request_id)`; identical replay avoids provider work and changed content returns 409.

Provider orchestration composes a coding projection into `GroundedTutorService`: existing retrieval planner, source policy, provider configuration, citation checks and Tutor turn APIs. Code bypasses academic deterministic-math repair and does not write academic correctness/mastery or adaptive goal completion. Advisory state remains read-only. The provider is called once; timeout is capped at 45 seconds or a lower configured value.

An in-process nonblocking per-database/session gate bounds overlapping work. It is explicitly a single-process local-server guarantee; it is not distributed coordination. Tutor's `atomic_exchange` takes an optimistic snapshot before generation and opens the write transaction only for persistence. Revalidation plus durable uniqueness/revision checks remain the backstop. Turns and coding context commit in the same connection/transaction or all roll back. A deliberately saved task can remain after a failed send.

Consent revisions/times and source identity/version allowlists are server generated under `coding_workspace_v1`, preserving unrelated metadata. Preview resolves bounded current retrieval candidates; clients never supply source authority. Before sending and before committing, the adapter checks source identity, course placement, current hash, extraction version, native generation, metadata revision, Trash/indexing/availability and original integrity. Native course aliases reuse the canonical retrieval repository's pinned identity map. No new OCR, original copy or retrieval index is created. Bound Academic Tutor sessions now consume their recorded `source_version_hash` too, including checks after generation before transaction commit.

Provider context has current-field (20k), history (8k), source excerpt (8k), operation-card (4k) and composed-message (40k characters/120k UTF-8 bytes) limits. Current request JSON is at most 24 KiB; source snapshot 16 KiB. Oldest history is omitted first, with an omission flag. Hint/solution-off projections omit prior full-solution exchanges. Rebuild has empty active history; prior transcript remains readable after reopening. Cards are reference material, not canonical evidence links.

Notebook export uses stdlib JSON and authored inert templates. `nbformat` is a development-only validation dependency. Every cell has a deterministic unique ID; code cells have null execution counts and empty outputs. No model-generated JSON, HTML rendering, provider call, source extraction export, arbitrary disk path or execution dependency is involved. Safe response filenames, attachment MIME, no-store and nosniff are enforced. Only trusted authored reference code executes in synthetic notebook tests.

The browser uses one transcript/composer with a bounded scrollable tools area. Code/output use escaped literal code nodes; prose uses the existing safe Tutor Markdown renderer. Copy preserves exact text. External Colab opens the fixed HTTPS homepage with noopener/noreferrer and no code in URL parameters. AJAX replaces only the server-rendered transcript after a committed receipt; task drafts remain in page memory. Callback generations prevent a delayed request from populating another active task. No paid work occurs on toggle, reopen, task save, export or card search.
